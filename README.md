# [W]三国志14优化启动器（三国志14 传承版：电脑 AI 优化、跳过回合报告）

Steam 版《三国志14 威力加强传承版》（`SAN14CE_SC.exe` 1.0.2.58226）的优化工具。最早只做「跳过回合开头的报告」（目录名 `SAN14_ReportSkip` 由此而来），后来加了电脑 AI 的优化，现在主要内容是 AI。

所有改动只在游戏运行时的内存里做：不修改、不添加游戏目录里的任何文件，关掉游戏就恢复原样，Steam 校验文件不受影响。

> **声明**：这是玩家自己做的非官方工具，与光荣特库摩（Koei Tecmo）无关，也没有得到其认可。需要你自己拥有正版游戏；本仓库和发布包不含任何游戏文件。工具在运行时修改游戏进程的内存，只用于单机游玩，风险自负。文中提到的其他社区 Mod 归各自作者所有，这里只说明如何与它们共存。

## 这个项目做了哪些事

### 一、读懂并改写电脑 AI

游戏的 AI 是数据驱动的行为树（`0000/bt_exce.bin`，势力、军团、军势、部队四棵树），节点算法和数值公式在 exe 里。网上没有公开的编辑工具，这里从头做了一套：

- **行为树工具**（`ai/`）：`btfile.py` 解析并能逐字节原样写回，`btdump.py` 把四棵树导出成可读文本，285 种游戏节点和 13 种引擎节点都对上了类名，条件节点和属性编号有字典（`info_names.json`、`node_types.json`）。
- **改树注入**：`btpatch.py` 按模块清单（`ai/modules/*.json`）生成改版树，`launch.py` 挂起启动游戏并注入 `bin/san14_ai.dll`，游戏读树时读到的是游戏目录外的改版。
- **每日执行层**（`aihook/san14_ai.cpp`）：树每旬只跑一次，要每天看局面、下令的逻辑写在 DLL 里，挂在游戏的推进状态上。
- **看海测试**（`ai/observe.py`、`autotest.py`、`ai/research/`）：自动看海、按日记录各势力和部队，每局跑完用 `research/check_modules.py` 和原版对比并扫描异常；各项改动的 A/B 脚本都在 `ai/research/`。

### 二、电脑 AI 的八个模块（启动器里可单独勾选）

只改电脑势力「怎么打」，不改「打不打、打谁」，各势力原版的性格不变（三处例外见使用说明）。阵型等数值从游戏里读，不写死。

| 模块 | 做了什么 |
|---|---|
| 出兵编成 | 迎击时几名强将平分兵力（最多 3 人），会锋矢的当侧翼，统率低的带少量兵用雁行 |
| 集结齐进 | 攻城主力先集结，攻城兵器跟本队；几个军势打同一座城时错开出发、城外会合；落单的部队等友军，不单打 |
| 会战协同 | 遇敌先会合再一起上；每天分配攻击目标（贴身的先打、够打了换下一支、锋矢优先打远程和兵器）；贴敌待命改还手 |
| 野战撤退 | 迎击打不过时整个军势一起撤回同一座城，附近军势同撤，不会一拨撤一拨打 |
| 雁行站位 | 雁行走到离敌两格放箭，被贴上就撤到友军身后 |
| 城下迎击 | 放开顶级难度下小势力被围不出城的限制；援军打完一波继续守；优先打攻城兵器；渡江迎击、半渡而击、水战守港 |
| 守关 | 关后只留雁行放箭，近战送回城，不在关后排长队 |
| 攻城评估 | 出兵门槛算上守方府加成和邻城援军，凑够才出；到城外先占周边的府；每天看粮道、防断粮 |

设计、每一版的假设和实测数据在 `ai/BEHAVIOR_PLAN.md`（五十节），打法规则在 `ai/TACTICS.md`，AI 运转流程在 `ai/AI_FLOW.md`，验收记录在 `ai/验收_2026-11-12.md`，试过但没进默认的模块在 `ai/modules/experiments/` 和 `archive/`。

### 三、其他功能

- **跳过回合报告、回看报告按钮**：回合开头不再弹两页报告；地图左下角加一个按钮随时回看（`bin/san14_overlay.dll` 直接画进游戏画面，全屏可用）。
- **自定义府加成**：分别设置我方和电脑的府加成。
- **看海时按 Esc 接管**：看海中途收回操作（`ai/TAKEOVER.md`）。
- **陷阱近身触发**：敌军走到陷阱旁 1 格才发动。
- **一起加载人力资源管理器**：第三方 Mod 放在游戏目录外加载（本仓库不含它的文件）。
- **启动器和发布包**（`launcher/`、`release/make_release.py`）：原生启动器 exe，自带免安装 Python，解压即用。

### 四、游戏更新后的适配

exe 带 SteamStub 壳、开了 ASLR，所有地址用特征码定位，集中在 `sigs/sigs.json`。游戏更新后 `tools/sigcheck.py` 按功能逐个检查，`tools/sigfind.py` 找回失效的特征码；对不上的功能单独停用并在游戏里提示，其余照常。

## 设计：游戏目录里不装任何文件

游戏保持原版纯净是硬要求：安装目录里不放 Mod 文件、补丁或备份，也不改游戏文件。常见 Mod 的三种装法在这里各有替代做法：

| 常见装法 | 这里怎么做 |
|---|---|
| 改 exe 或给 exe 打补丁 | 游戏启动后在内存里改（`tools/patch.py`、两个 DLL 的内联钩子）。exe 带 SteamStub 壳，磁盘上的代码本来就是加密的，等内存里解密后再按特征码定位 |
| 覆盖数据文件（如 AI 行为树 `0000/bt_exce.bin`） | 改版树生成到本工程的 `ai/build/`。`ai/launch.py` 用挂起方式启动游戏，在游戏代码运行前把 `san14_ai.dll` 排进主线程（APC）；DLL 换掉导入表里的 `CreateFileW`，游戏打开 `bt_exce.bin` 时实际打开的是游戏目录外的改版 |
| 把 DLL 放进游戏目录让游戏自动加载（如 `dinput8.dll`） | DLL 留在本工程的 `bin/`，由启动器从外部注入（`LoadLibraryW`） |

结果：关掉游戏就恢复原样，Steam 校验文件永远通过，卸载就是删掉本工具的文件夹。代价是每次都要用本启动器开游戏，改了勾选要重开游戏。

游戏更新后地址会变，所以不写死地址，全部用特征码找（见上面「游戏更新后的适配」）；找不到时该功能自动停用、游戏照原版运行，不会带着错位的补丁硬跑。

## 和「人力资源管理器」一起用

「三国志14人力资源管理器」（作者勿知鸦，闭源免费）是别人的 Mod，本仓库和发布包都不带它的文件。它原本的装法是把自己的 `dinput8.dll` 放进游戏目录，和上面的要求冲突，所以做了一层兼容，让它在游戏目录外照常工作：

- **从外面加载**：用户把自己那份 `dinput8.dll` 放在游戏目录以外（例如启动器文件夹里的 `第三方Mod\`），在启动器里选中它。它是 dinput8 代理版，要游戏第一次调用 `DirectInput8Create` 时才启动，单纯注入进去不会工作；所以 `san14_ai.dll` 把游戏导入表里的 `DINPUT8!DirectInput8Create` 指到自己，第一次调用时加载用户的那份 DLL 并转给它，它再转给系统的 dinput8，和装在游戏目录里时的启动过程一样。
- **它写的文件也不进游戏目录**：它会往游戏目录的 `SAN14HR\` 写日志和配置，这些读写（它的 kernel32 导入表里 10 个文件函数）被改到本工具的 `logs\san14HR\`。
- **屏蔽命令书按钮**（可选，默认开）：它装这个按钮时要交换界面对象的几个虚表槽，我们先把这几个槽换成转发跳板，它比较交换失败就自己放弃这一项，其他功能照常。
- **功能冲突自动让开**：和「跳过回合报告」同开时，它的 F8 等 4 项检测到冲突会自己让出；想用它的 F8，取消勾选跳过报告即可。
- 加载失败（路径不对、版本不认）时游戏照常启动，只是没有它的功能。已测它的 0.6.1 版。

和「三国志14 优化伴侣」的共存方式（检测到它的钩子就让开、回看报告改为替用户按 F8）见 `docs/开发笔记.md`。

## 怎么用

玩家用发布包「[W]三国志14优化启动器」：解压到任意位置，双击里面的 exe，勾选功能后点「启动游戏」。说明见 `release/使用说明.txt`（打包时会放进发布包）。发布包在本仓库的 Releases 页面下载。

## 编译和发布

**一步完成：双击根目录的 `build_release.bat`**（或运行 `python -P release/make_release.py`）。它依次做：

1. 编译两个 DLL 和启动器 exe（调用 `overlay/build.py`、`launcher/build.py`、`aihook/build.py`）。
2. 组装可运行的文件夹 `dist/[W]三国志14优化启动器/`：启动器、自带的免安装 Python 和 Pillow、脚本、特征码清单、DLL、AI 模块、使用说明、许可证。
3. 用包里自带的 Python 做冒烟测试：脚本能导入、特征码清单在已测版本的镜像上全部对得上、AI 模块能在本机游戏的行为树上生成。
4. 压成 `dist/[W]三国志14优化启动器_v<版本号>.zip`，并检查里面没有别人 Mod 的文件。

版本号取自 `tools/report_button.py` 的 `VERSION`。游戏和启动器要先关掉，否则正在使用的文件换不了。`dist` 文件夹里的 `settings.ini` 和 `第三方Mod\` 重建时保留，`第三方Mod\` 不进 zip。发新版时再把 zip 传到 GitHub 的 Releases 页面。

环境（Windows 10/11 64 位）：

| 需要 | 默认路径 | 环境变量（放在别处时设置） |
|---|---|---|
| Python 3.13 和 Pillow（`python -m pip install --user pillow`） | 系统里的 `python` | |
| [llvm-mingw](https://github.com/mstorsjo/llvm-mingw)（`ucrt-x86_64` 版）的 `bin` 目录 | `E:\Tools\extracted\llvm-mingw\llvm-mingw-20261020-ucrt-x86_64\bin` | `SAN14_LLVM` |
| python.org 的 Python 3.13 免安装版（embeddable package）解压后的文件夹 | `E:\Tools\extracted\python-3.13.16-embed-amd64` | `SAN14_PY_EMBED` |
| Pillow 12.3.0 的 `cp313-win_amd64` wheel 解压后的文件夹 | `E:\Tools\extracted\pillow-12.3.0-cp313-win_amd64` | `SAN14_PILLOW` |

只想单独编译某一部分（产物都是静态链接，只依赖系统 DLL）：

```bash
python -P aihook/build.py      # bin/san14_ai.dll
python -P overlay/build.py     # bin/san14_overlay.dll
python -P launcher/build.py    # 启动器 exe 和图标
```

两个 DLL 的 `build.py` 会先由 `sigs/sigs.json` 生成 `sigs_gen.h`。仓库里的 `bin/*.dll` 是已经编译好的。

离线测试（不用开游戏）：`python -P tools/test_sigs.py`、`python -P ai/test_btpatch.py`。

更细的开发记录（游戏更新后怎么适配、跳过报告的实现、游戏里的结构和地址、走过的弯路、工具表）在 `docs/开发笔记.md`，AI 部分在 `ai/README.md`。
